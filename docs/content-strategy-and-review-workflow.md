# 内容策略、审核与发布后复测工作流

**适用范围：** 企业级 GEO 工作区中的「内容策略与智能写作」模块。本文描述从真实平台基线到内容发布后观测的受控闭环，以及各角色应承担的审核责任。

## 一、这不是“自动发文工具”

本系统用于把已完成的 GEO 评估、Query Gap、竞争/来源证据转化为可审核的内容计划和草稿。它不承诺引用率、排名、流量、线索或收入提升，也不会把模型生成文本当成已验证事实或已发布内容。

- **正式 GEO 基线**必须来自客户侧 Browser Agent 在真实 AI 平台网页的可见执行结果，或有明确标识的受控人工导入。
- 模型 API 只用于辅助生成 Query、内容策略、草稿或分析；API 结果不能被当作真实平台网页基线。
- 系统不自动向官网、知乎、微信公众号、Medium、LinkedIn 或其他外部渠道发布内容。
- 外部发布由内容负责人完成，并以 URL、发布时间和证明材料登记回系统。

## 二、受控工作流

```text
真实平台基线 / 受控人工导入
  → GEO 诊断与 Query Gap
  → 市场包、来源与竞品证据审核
  → 内容机会
  → 内容策略
  → Content Brief
  → 受控模板或 LLM 草稿
  → Claim / 渠道规则审核
  → 批准快照
  → 人工发布登记
  → 复用原始 Dataset 的发布后复测
  → 可见度与报告对比
```

### 1. 建立前置证据

在进入内容模块前，分析人员应完成：

1. 使用已批准、不可变的 Query Dataset 在已选定的平台执行基线；
2. 由诊断流程识别 Query Gap、引用缺口、品牌/竞品出现情况及不确定性；
3. 审核可用的市场包、来源证据包和竞争证据。

没有基线与诊断时，「内容机会」会显示为空状态。这是刻意的企业控制：系统不会用演示数据伪造内容依据。

### 2. 从内容机会创建策略

策略负责人从「内容机会」选择一个真实诊断，创建内容策略。策略必须明确：

- 目标 Query 范围；
- 目标渠道；
- 受批准的市场包与证据包；
- CTA、内链策略、验收标准；
- 禁止使用或需要人工确认的主张。

系统会校验 Query 是否属于该诊断关联的不可变 Assessment Run / Dataset、渠道是否处于市场包允许范围、证据包是否已批准。任意把无关 Query、渠道或证据混入策略的做法会被拒绝。

策略创建后仍处于待审核状态。只有审核通过的策略可以创建策略绑定的 Content Brief。

### 3. 创建与审核 Content Brief

Brief 是草稿的唯一业务输入，至少应记录：

- 目标 Query Cluster、市场/语言与渠道；
- 对应的 Query Gap / GEO 诊断；
- 可用来源、竞争证据和关键事实；
- 推荐结构、CTA、链接建议；
- 禁止主张与渠道规则；
- 验收标准。

审核人应把没有证据支持的关键说法视为风险，而不是事实结论。Brief 获批后才能进入智能写作。

### 4. 生成草稿：模板与 LLM 的边界

从已批准 Brief 可生成两类草稿：

| 类型 | 适用场景 | 模型调用 | 产出状态 |
| --- | --- | --- | --- |
| 受控模板草稿 | 希望先用固定结构快速形成可编辑版本 | 不调用外部 LLM | `needs-review` |
| 模型草稿 | 已配置、已测试并可执行的 OpenAI-compatible 模型连接 | 调用指定模型，保存模型/Prompt 元数据 | `needs-review` |

无论来源，草稿均为临时文本：**不等于已发布、不等于已验证事实、不会创建外部分发动作。**

编辑草稿后，系统会重新检测 Claim，并清空此前的 Claim 判断和审批状态，要求重新审核。这样可避免“先审批、后换文”的绕过行为。

### 5. Claim、链接与渠道审核

审核人需要逐项确认：

- 关键 Claim 是否有已批准 Brief 证据支持；
- 是否触犯禁止主张；
- 必需链接是否缺失、失效或不符合渠道规则；
- 是否存在尚未解决的渠道政策风险。

出现未解决的关键 Claim 或风险时，草稿不能被批准。审核动作会留下审计记录；当前“以 Brief 证据支持”是 Brief 级证据确认，后续可再升级为更细粒度的 evidence item 选择。

### 6. 人工发布登记

审核通过后，内容负责人必须在实际外部发布完成后，登记：

- 已批准的草稿快照；
- 实际发布 URL；
- 渠道；
- 发布时间；
- 发布证明说明（系统保存内部 proof artifact）；
- 可选补充说明。

登记不会替用户发布内容，且只能关联已批准快照。登记资料用于报告溯源和后续复测，而不是作为“已获得 GEO 成效”的证明。

### 7. 发布后复测

发布登记完成后，可创建单次、每周或每月的复测计划。复测必须：

- **复用原始不可变 Query Dataset 与既定 Query Scope**；
- 作为“发布后观察（post-publication observation）”呈现；
- 与发布前基线并列比较；
- 不得覆盖、重写或替代原始基线。

正式网页复测仍通过客户侧 Browser Agent 执行；无法自动执行时，可使用受控人工导入并清楚标明来源与限制。

## 三、推荐角色分工

| 角色 | 主要职责 | 不可执行的高风险动作 |
| --- | --- | --- |
| 管理员 | 管理工作区、模型连接、Browser Agent 与授权范围 | 不应以管理员权限替代内容审核证据 |
| 分析师 | 维护 Query、发起基线与诊断、创建策略/Brief/草稿 | 不能把 API 结果标为真实平台基线 |
| 审核人 | 审核策略、Brief、Claim 与草稿，确认例外说明 | 不应批准未解决的关键风险 |
| 内容负责人 | 在外部渠道实际发布并登记 URL / 时间 / 证明 | 不能把未批准草稿直接作为受控发布记录 |
| 查看者 | 查看被授权的诊断、内容状态和报告 | 无配置、审批或发布登记权限 |

## 四、上线前检查清单

- [ ] Query Dataset 已批准，且基线运行已完成或明确标识为人工导入。
- [ ] GEO 诊断、市场包和证据包均已准备并通过审核。
- [ ] 内容策略的 Query、渠道、证据均在诊断与市场包的合法范围内。
- [ ] Brief 已通过审核；禁止主张和验收标准已填写。
- [ ] 草稿的关键 Claim、链接和渠道风险已解决，草稿已批准。
- [ ] 人工实际发布后已登记准确 URL、时间和证明材料。
- [ ] 后续复测绑定的是原始 Dataset，并在报告中标注为发布后观察。

## 五、数据、隐私与审计边界

- 模型连接密钥必须由安全配置/引用机制保存，任何 API、工件或导出记录不得包含明文凭据。
- Browser Agent 不读取、不上传客户密码或 Cookie；不得绕过登录、验证码、访问控制、反爬机制或平台条款。
- 证据、审批、发布证明与复测记录按工作区隔离；跨工作区查看、审批或引用均应被拒绝并记录。
- 执行失败、需要人工处理、未识别引用和人工导入都必须保留状态与原因，不能用推断结果补齐。

## 当前 Content Studio 交付方式（2026-09-29）

内容模块当前采用三步工作流，而不是让内容负责人手工重复填写策略字段：

1. **内容机会**：从已经完成真实网页采集和 GEO 诊断的 Query Gap 中选择机会。系统锁定对应的不可变 Query 范围、首轮诊断、已批准事实包、市场包、来源和禁止主张。
2. **AI 生成方案**：内容负责人只选择渠道、内容类型、写作 Profile 与已验证的内容模型连接。系统调用该模型生成一个可审核的内容方案，并保存模型身份、Profile/版本、Prompt 版本与 Prompt 工件。输出为待审核 Brief，不是已发布内容。
3. **AI 写作与审核**：只允许从已批准 Brief 发起模型草稿。界面显示模型、写作 Profile、Prompt 版本和事实边界；无已验证模型时默认阻止调用。若选择“受控模板（不调用模型）”，系统会明确标识该草稿没有调用模型。主张审核通过后，用户只能复制或下载 Markdown，由内容负责人手动上传到外部渠道。

当前版本**不在 Content Studio 内自动发布或登记 URL，也不把复测当作内容交付的必填步骤**。后续的真实平台观察应从“持续监控 / 多平台测试”独立发起，并复用原始不可变 Dataset。

### 写作 Profile

内置可版本化 Profile：B2B 产品教育型、选型决策指南、技术 Help Center / FAQ、中立对比说明。每个 Profile 固定声明语气、渠道指导、系统指令和输出合同；实际执行时将 Profile、模型和渲染后的 Prompt 一并留存在 Prompt 工件中，方便审核与追溯。

### 自定义 Prompt Profile、版本与草稿恢复（2026-09-29）

除只读的系统模板外，工作区管理员或具备写入权限的成员可以在「AI 生成方案」中打开 **新建 / 管理**，创建适合特定渠道、内容类型和品牌写作规范的 Profile。每个工作区 Profile 都包含：

- 名称与用途说明：帮助团队在生成前选择正确的写作任务；
- 渠道标签、内容类型标签与写作语气：用于在界面中快速匹配官网 Blog、Help Center、知乎、公众号、Medium、LinkedIn 等场景；
- 渠道写作策略：规定文章的组织方式、CTA 和渠道边界；
- 系统指令与输出结构/验收规则：会被实际拼入模型调用，而不是只作为页面说明文字。

保存一个工作区 Profile 会创建可追溯的版本。更新同一模板会递增版本号；归档会阻止它继续用于新的内容方案，但不会删除历史记录。生成 Content Brief 时，系统会保存所选 Profile 的完整快照、渲染后的 Prompt、模型身份和证据边界。随后从该 Brief 生成草稿时，默认继续使用该快照，即使原模板之后被编辑或归档，也不会静默改变历史内容的生成依据。

模型生成的草稿会立即持久化为待审核记录，并出现在「已保存草稿（刷新页面后仍可继续）」列表中。内容负责人可直接编辑 Markdown 并点击「保存修改」；保存会更新后端记录、重新执行 Claim 检测并清除先前审批状态。这样可以在刷新、关闭浏览器或切换模块之后恢复草稿，同时避免修改已审批文稿却沿用旧审批结论。
