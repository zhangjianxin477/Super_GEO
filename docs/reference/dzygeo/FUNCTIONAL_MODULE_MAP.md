# 达准源公开前端：功能模块与产品工作流映射

> 参考范围：公开首页可见内容与交互描述（不包含登录后的私有后台）。  
> 目的：提炼功能逻辑和模块依赖，用于 GEO Harness 的通用企业版信息架构。

## 核心结论

参考产品不是“一个模型任务执行器”，而是一个以 **诊断报告** 为中枢的 GEO 工作流产品：

`品牌诊断 → 发现问题 / 竞品差距 → 建立长期监控 → 建立对外知识资产 → 生成内容 → 发布后复测 → 报告交付`

用户先看到结果和下一步，不先看到 Provider、队列、API Key、原始证据 JSON 等基础设施。

## 公开页面呈现的模块

| 模块 | 公开页面描述的功能 | 输入 | 主要输出 | 后续入口 | 适配 GEO Harness |
|---|---|---|---|---|---|
| 品牌诊断 | 模拟真实用户向多个 AI 引擎提问，识别品牌表现 | 品牌、行业、地区、官网等 | 提及率、推荐排名、口碑/情感、信源引用、竞品对比、网站 GEO 健康度 | 报告、监控、知识资产、内容优化 | **产品主入口** |
| 问题监控 | 对选定品牌问题持续复测，追踪 AI 回答变化 | 已验证的 Query、模型范围、频率 | 按天的提及率、排名、口碑、信源趋势与异常 | 预警、周期报告、复测明细 | **诊断后建立** |
| 快速调研 | 公开页仅说明为快速赛道/行业摸底，约 3–5 分钟出报告 | 行业/赛道、可能的品牌/问题 | 赛道摸底报告 | 竞品差距、诊断或内容策略 | **对应竞品与信源研究** |
| 知识图谱构建 | 为企业建立对外表达的统一事实底稿 | 诊断结论、品牌资料、信源、竞品证据 | 推荐榜单/差距归因、对外宣传知识库、企业档案、版本管理 | 内容生产 | **对应知识资产 / Product Graph** |
| AI 文章创作 | 基于知识库生成可发布文章 | 已审核知识资产、内容目标、渠道模板 | SEO/渠道文章、多模板、自动配图、飞书同步 | 人工审核、发布、复测 | **对应 Evidence-grounded Content Studio** |
| 抖音图文生成 | 将诊断结论、知识库转为图文海报 | 诊断 / 知识资产 / 模板 | 竖版图文、云端预览、下载 | 渠道发布 | 作为后续渠道插件，不是首期核心 |
| 可视化报告 | 用一页清楚展示品牌、竞品与短板 | 诊断 / 监控 / 复测数据 | 分享链接、客户交付报告 | 优化行动、续费/服务交付 | **诊断和复测的交付中心** |

## 公开页面明确给出的首次使用流程

1. **输入品牌信息**：品牌名、行业、地区、官网等；
2. **AI 模拟真实提问**：生成“哪家好、怎么选、值不值”等用户问题；
3. **回答采集与分析**：识别品牌提及、位置/排名、评价倾向、引用信源；
4. **生成诊断报告**：形成可视化报告，作为优化前基线。

## 应迁移到 GEO Harness 的通用产品结构

### 一级业务导航（面向业务用户）

1. **品牌诊断**：创建 / 执行 / 查看诊断；
2. **问题监控**：从诊断中选择高价值 Query 追踪；
3. **行业与竞品研究**：信源、内容布局、竞品被引用原因；
4. **知识资产**：品牌事实、产品实体、来源、禁止主张、版本；
5. **内容行动**：Content Brief、渠道草稿、审核、发布登记；
6. **报告中心**：诊断、监控、复测、可分享客户报告。

### 管理员二级区（Harness 底座）

- 模型连接与凭据；
- 自动 Provider Adapter、企业网关、MCP；
- 受控人工批量导入；
- 执行队列、失败恢复、并发/限流；
- 审计、角色、数据留存与工作区设置。

## 关键页面间的动作关系

```text
创建品牌诊断
  → 品牌事实包
  → AI 生成 / 人工审核 Query Dataset
  → 自动连接或受控人工采集
  → 诊断报告
     ├→ 建立问题监控
     ├→ 竞品与信源研究
     ├→ 建立知识资产
     ├→ 创建 Content Brief / 草稿
     └→ 发布登记 → 相同 Dataset 复测 → 对比报告
```

## 当前实现需要停止作为主线的内容

- 首屏直接展示 700 条 Query × 模型执行量；
- 强制用户先处理“一条 AI 回答”；
- 让 Provider 连接设置成为首要操作；
- 将 JSON 批量导入作为业务用户的显式主 CTA。

这些保留在管理员或执行明细中即可。

## 公共内容无法确认的部分

公开首页没有披露其登录后各页面的实际字段、权限、状态机、接口或异常处理；对于“快速调研”的详细输入输出也只给出了高层描述。不能把未公开细节当成其已验证实现。
