# 达准源公开首页前端参考审计

> 抓取日期：2026-09-27（公开首页）  
> 参考地址：https://dzygeo.com/#what-is-geo  
> 原始公开 HTML：`docs/reference/dzygeo/home.html`  
> 用途：梳理信息架构、任务流和交互层级；不复制对方品牌、素材、具体文案或私有代码。

## 1. 页面信息架构（从上到下）

1. **首屏 Hero**：一句用户场景痛点 + 一句价值承诺；主行动为登录/开始使用，次行动为了解 GEO。
2. **免费问题监控**：用一张动态数据样张说明“创建一个问题后持续复测”的产品价值。
3. **诊断报告样张**：提前展示用户最终拿到的可交付物——可见度、口碑、信源、排名、AI 回答与引用。
4. **GEO 科普**：三个痛点卡 + GEO 定义 + SEO/GEO 对比。
5. **核心功能**：问题监控、品牌诊断、知识图谱、内容创作、渠道内容生产等能力，均按结果而非技术模块表述。
6. **四步流程**：输入品牌资料 → 生成真实用户问题 → 回答采集与分析 → 生成可视化报告。
7. **适用对象**：品牌方/企业主、服务商两类人群。
8. **FAQ / 最终 CTA / 联系方式 / Footer**。

## 2. 参考站首页的关键产品逻辑

### 核心入口：先做一次“品牌诊断”

用户不先看到原始任务队列、Provider 配置或 100×N 执行单元；而是先理解并完成一个有明确结果的任务：**诊断当前品牌在 AI 回答中的可见度**。

诊断的内部动作被归并成四步：

1. 输入品牌、行业、地区、官网与必要背景；
2. 系统基于资料生成模拟真实用户问题；
3. 系统并行采集模型回答并分析品牌、竞品、排名、情感、引用；
4. 汇总为可分享的诊断报告，作为后续优化基线。

### 诊断之后：监控、调研、知识资产、内容、复测

参考站将复杂能力放在“先拿到诊断结论”之后：

- 从高价值问题建立长期监控；
- 从诊断和竞品证据进入行业调研；
- 将品牌事实、信源、差距沉淀为知识图谱/对外知识库；
- 根据诊断缺口生成渠道内容；
- 发布后按原 Query 集合复测并呈现趋势/报告。

## 3. 当前 GEO Harness 与该逻辑的偏差

当前实现过早暴露了企业底座：市场包、工作区、连接器状态、700 个 Query × 模型队列、人工导入 JSON。它们是企业后台能力，但**不应该是新用户的第一屏主任务**。

这造成三个问题：

- 用户不知道“我现在到底要完成什么”；
- “一条回答 / 700 条任务 / 批量导入”同时出现，主线冲突；
- 业务价值没有先通过“诊断报告”表达，页面像内部运维台而不是 GEO 产品。

## 4. 建议重构后的产品工作流（通用企业版）

### A. 对外首页 / 新用户入口

`品牌诊断` 是唯一一级主 CTA。首页结构参照上述 IA，但使用 GEO Harness 自己的视觉和文案：

- Hero：让 AI 更准确理解、引用与推荐你的品牌；
- 结果样张：提及率、推荐率、引用率、竞品差距、来源覆盖；
- GEO 教育：SEO vs GEO；
- 产品能力：品牌诊断、问题监控、竞品/信源研究、知识资产、内容与复测报告；
- “4 步完成基线诊断”；
- 适用人群、FAQ、CTA。

### B. 登录后的任务主线

1. **创建品牌诊断**：填写品牌事实（产品、受众、官网、目标市场、竞品、渠道）。
2. **生成并审核 Query 集**：AI 依据事实包、行业/竞品和渠道生成候选 Query；人工可编辑、去重、审批。每条 Query 必须显示来源、意图、生成理由。
3. **配置执行方式**：
   - 已授权 API / 企业网关 / MCP：自动执行；
   - 没有授权连接器：受控人工批量导入。
   该步骤只在需要时展示，不能抢占主线。
4. **后台执行 + 状态页**：显示“诊断正在进行”，按模型、问题、完成率汇总，不把 700 条原始单元塞到首页。
5. **生成诊断报告**：结果页首先回答“AI 怎么看你、竞品在哪、哪些来源缺失、下一步应该补什么”。
6. **从报告进入行动**：
   - 建立问题监控；
   - 建立竞品与信源研究；
   - 生成证据驱动知识资产；
   - 创建 Content Brief 和渠道草稿；
   - 登记发布证据；
   - 用同一 Dataset 复测并生成前后对比报告。

### C. 企业 Harness 底座的位置

Harness 保留，但降到“执行设置 / 管理员后台”：

- Provider Adapter、API Key、MCP、限流、审计；
- 批量任务导出/导入；
- 证据工件、执行重试、失败恢复；
- 租户、角色、数据留存、审批。

它为产品主流程提供能力，不成为普通用户看到的首页产品叙事。

## 5. 前端重构原则

- 采用**结果导向导航**，而不是技术组件导航。
- 每个页面只能有一个明显的下一步行动。
- 新用户的首页不展示“执行队列”“模型连接”“人工导入”等实现细节。
- 执行中的状态应展示为“本次诊断进度”和“预计可得到的报告”，原始 Query × Provider 单元只在高级明细中查看。
- 不照抄参考站的品牌、图像、文案、数据、付费策略或页面代码；只参考其信息层级、任务编排和结果展示方式。

## 6. 后续实施前必须确认的页面范围

1. 公共官网 Landing；
2. 登录后首页（诊断列表 + “新建品牌诊断”）；
3. 创建诊断向导；
4. 诊断执行进度页；
5. 诊断报告页；
6. 报告驱动的监控 / 研究 / 知识资产 / 内容 / 复测页面；
7. 管理员 Harness 设置区。
